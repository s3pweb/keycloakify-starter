# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The B2PConnect Keycloak theme, named **`b2pconnect`** (`themeName` in `vite.config.ts`), built with [Keycloakify v11](https://docs.keycloakify.dev) (React 18 + Vite + TypeScript). The output is a set of `.jar` files deployable into Keycloak:

-   `keycloak-theme-for-kc-22-to-25.jar` — current prod (Keycloak 24.0.5);
-   `keycloak-theme-for-kc-all-other-versions.jar` — Keycloak 26 (migration target).

It contains a React **login theme** and a native FreeMarker **email theme** (`src/email`). There is no account theme (`accountThemeImplementation: "none"`).

The migration from Keycloak 24 to 26 is planned in `plans/migration-keycloak-24-to-26.md` (server blockers, theme impact, steps, open questions): read it before changing the theme or the test environment.

## Commands

`keycloakify` is pinned to an exact version: when upgrading it, update `package.json`, `yarn.lock` and `package-lock.json` together.

```bash
yarn install
yarn dev                     # Vite dev server (shows "No Keycloak Context" unless a mock is enabled, see below)
yarn storybook               # Storybook 8 on :6006
yarn build                   # tsc type-check + vite build
yarn build-keycloak-theme    # build + `keycloakify build` → dist_keycloak/keycloak-theme-*.jar (requires Maven >= 3.1.1 and Java on PATH)
yarn format                  # prettier --write (do not reformat src/login/main.css: its first line is kept as is)
npx eslint .                 # lint (no npm script for it)
```

Test environment (Docker, see `makefile`):

```bash
make start-server [KC_VERSION=26.8.1] [KC_PORT=8080]   # Keycloak + theme + maildev (fake SMTP, UI on :1080)
make test-e2e [KC_PORT=8080] [LABEL=kc]                 # e2e checks against the running server
make save-server-realm [SAVE_KC_VERSION=24]             # realm edited in the admin console → realm/realm.json (secrets removed)
```

-   Run Keycloak with `make start-server`, not `npx keycloakify start-keycloak` directly: it needs the `keycloakify-test` Docker network shared with maildev (the realm SMTP host is `maildev`).
-   One Keycloak at a time (keycloakify reuses the container name).
-   Test realm `myrealm` (`realm/realm.json`, test fixture only): `testuser` / `password123`; admin console `admin` / `admin` (override in e2e with `KC_TEST_PASSWORD` / `KC_ADMIN_PASSWORD`).
-   `make test-e2e` needs Google Chrome, curl, jq and node. It checks the login page (logo, realm title hidden, background, languages, French, wrong password, login redirect), the two emails sent through the admin API (B2PConnect logo and footer) and the required-action pages reached from the email link. Screenshots go to `e2e/screenshots/` (git-ignored). Run it on both 24.0.5 and 26.8.1 before committing a theme change.

Keycloakify CLI commands referenced by the project:

-   `npx keycloakify update-kc-gen` — regenerates `src/kc.gen.tsx` (also regenerated by the Vite plugin). Never edit that file by hand.

## Architecture

Runtime flow: Keycloak renders an FTL page that injects `window.kcContext` → `src/main.tsx` → `KcPage` in `src/kc.gen.tsx` dispatches on `kcContext.themeType` → lazy-loads `src/login/KcPage.tsx` → which switches on `kcContext.pageId` (e.g. `"login.ftl"`, `"register.ftl"`).

-   `src/login/KcPage.tsx` — the customization point. Every page falls through to `default:` → keycloakify's `DefaultPage` with keycloakify's stock `Template` (`keycloakify/login/Template`) and default CSS (`doUseDefaultCss={true}`). To customize a page, add a `case "<page>.ftl":` returning your own component. The `classes` object overrides keycloak CSS class keys (`ClassKey`) globally.
-   `src/login/main.css` — the B2PConnect branding: background `#313F50`, and the logo `src/login/assets/logo-b2pconnect.png` shown as the background of `#kc-header-wrapper`, whose children (realm name / `displayNameHtml`) are hidden.
-   `src/login/KcContext.ts` — extends the typed `KcContext`. `KcContextExtension` is for properties on every page, `KcContextExtensionPerPage` for per-page additions.
-   `src/login/i18n.ts` — `i18nBuilder`; add custom message keys / languages here.
-   `src/login/KcPageStory.tsx` — exports `getKcContextMock` and `createKcPageStory`, used by the stories in `src/login/pages/*.stories.tsx`. Stay on Storybook 8: import `Meta` / `StoryObj` from `@storybook/react`, not from `kc.gen`.
-   `src/email/` — native FreeMarker email theme (`parent=base`): `html/template.ftl` holds the B2PConnect layout (logo loaded from b2pconnect.com, footer), `html/*.ftl` / `text/*.ftl` the emails, `messages/` the translations. Not React: keycloakify copies it into the jar as is.
-   `src/kc.gen.tsx` — generated: theme name, `KcEnvName`s, and the theme-type dispatcher.
-   `e2e/` — `run.sh` (entry point), `login.mjs`, `required-actions.mjs` (Playwright via `playwright-core`, driving the installed Chrome).
-   `scripts/save-server-realm.mjs` — used by `make save-server-realm`.

### Previewing a page with `yarn dev`

Uncomment the block in `src/main.tsx` that sets `window.kcContext = getKcContextMock({ pageId: ..., overrides: {} })`. Re-comment it afterwards — leaving it in increases bundle size.

## CI / releases

-   `.github/workflows/ci.yaml`: on push/PR to `main`, runs `build-keycloak-theme`. On push, if `package.json` `version` was bumped, it creates a GitHub release with `dist_keycloak/keycloak-theme-*.jar`. **To release: bump `version` in `package.json` and push.** Requires "Read and write permissions" for workflow tokens in the repo settings.
-   `.github/workflows/publish.yaml` (manual dispatch) uploads from `build_keycloak/target/*`, which is the pre-v11 output path — it does not match the current `dist_keycloak/` output.
